## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Task 1 as literally specified caused a ~300-test regression**
- **Found during:** Task 3 (first `mvn verify` run after Tasks 1+2)
- **Issue:** Adding `.id(UUID.randomUUID())` to the shared `createEntity()` factories while `@GeneratedValue` was still present broke every other test in each file that reused those factories as raw JPA fixtures (nested FK dependencies via `em.persist()`, `@BeforeEach`-populated fields via `repository.saveAndFlush()`), because Hibernate's unsaved-value detection for generated ids treats any non-null id as "must already exist."
- **Fix (intermediate):** Moved the id assignment to the DTO, only inside each `create*()` test (commit `d6672e0`). This eliminated the regression (0 errors) but left the original 10 tests failing with HTTP 409, because `repository.save()` on a `@GeneratedValue` entity with a non-null-but-new id routes through `merge()`, which throws instead of inserting.
- **Files modified:** All 10 `*ResourceIT.java` test files (twice — once for the intermediate fix, once more to reach the final state).
- **Verification:** Full `mvn verify` after each attempt; final state is 432/432 passing.
- **Committed in:** `d6672e0` (intermediate), `22d7118` (final)

**2. [Rule 4 → resolved] Architectural conflict between Option A and `@GeneratedValue`**
- **Found during:** Task 3, after the Rule 1 fix above still left 10 tests failing with 409 Conflict (`ObjectOptimisticLockingFailureException`)
- **Issue:** `@GeneratedValue` on all 10 domain entities' `id` field is architecturally incompatible with "client always supplies the id" — confirmed empirically (uniform 409 across all 10 `create*()` tests, 0 unrelated collateral damage) and traced to Hibernate's merge-path unsaved-value strategy.
- **Resolution:** Per Rule 4 (architectural change), this was escalated to the user rather than resolved unilaterally. The user approved removing `@GeneratedValue` from all 10 domain entities, after reviewing the verified-safe Liquibase schema evidence.
- **Fix:** Removed `@GeneratedValue` (commit `9c51249`); this predictably broke ~384 tests that relied on auto-generation (a different, expected failure mode: "Identifier ... must be manually assigned before calling 'persist()'"). Restored `.id(UUID.randomUUID())` to the shared fixtures (commit `22d7118`), which is now safe with no generator to conflict with, and removed the now-redundant DTO-level id assignment.
- **Verification:** Full `mvn verify`: 432/432 passing, 0 failures, 0 errors. `spotless:check` and `checkstyle:check` both clean.
- **Committed in:** `9c51249`, `22d7118`
